# decisions

* [DECISION-01: jag fails clearly when the model is not available](DECISION-01.md) - When the key is missing or out of credit, or the service is down, jag fails with a clear message and does not fall back to word-match ranking.
* [DECISION-02: Release 1 does not serve users whose text must stay on the machine](DECISION-02.md) - Release 1 needs the model service; users whose text must not leave the machine wait for a later local model option.
* [DECISION-03: jag reads the key from two variables and a config file, in a fixed order](DECISION-03.md) - jag reads JAG_TYPESAFE_API_KEY, then TYPESAFE_API_KEY, then ~/.config/jag/config.yml; the first key found wins.
* [DECISION-04: The health check examines five items with one free call](DECISION-04.md) - The health check examines key present, key valid, credit left, service reachable, and key file safe, with one call that costs almost nothing.
* [DECISION-05: jag keeps rg exit codes and adds one code for each model failure](DECISION-05.md) - jag keeps the rg exit codes 0, 1, and 2, and gives each model failure its own code above 2.
* [DECISION-06: A model failure during a search fails the full search](DECISION-06.md) - When the credit or the service stops during a search, jag returns no partial result and exits with the code of the cause.
* [DECISION-07: Errors are structured in structured output mode](DECISION-07.md) - In structured output mode, an error is structured, with the cause, the fix, and the exit code; in text mode, it is readable text.
* [DECISION-08: Setup asks before it replaces a key, and one command removes it](DECISION-08.md) - Setup asks the user before it replaces a stored key, and one command removes the stored key.
* [DECISION-09: The missing-key message tells a new user where to get a key](DECISION-09.md) - When no key is found, the message gives the page where the user gets a TypeSafe key.
* [DECISION-10: A result is a matching line with the lines around it](DECISION-10.md) - A result is the matching line with a few lines before and after it; matches near each other join into one result.
* [DECISION-11: When nothing answers well, jag labels the best results and exits 1](DECISION-11.md) - When no result answers the question well, jag shows the best results with a clear no-good-answer label and exits with code 1.
* [DECISION-12: The cost limit has a default that the user can change](DECISION-12.md) - jag has a fixed default cost limit, stated as a count of results to score, and the user can change it with an option.
* [DECISION-13: Reaching the cost limit has its own exit code](DECISION-13.md) - When jag reaches the cost limit, it returns the ranked results, says how many matches it skipped, and exits with its own code; exit 1 wins when nothing answers well.
* [DECISION-14: A folder search works as rg does and skips noise files](DECISION-14.md) - jag searches each subfolder and skips binary, hidden, and ignored files, as rg does; only --ask and --json say how many files it skipped.
* [DECISION-15: A result path has the same form as in rg](DECISION-15.md) - The path of each result follows the form of the folder that the user gave.
* [DECISION-16: A joined result shows its line range and marks each matching line](DECISION-16.md) - A result gives its first and last line, and it marks each line that matches the term.
* [DECISION-17: With --ask or --json, jag cuts a very long line and marks the cut](DECISION-17.md) - A result shows the exact source text; with --ask or --json, jag cuts each line that is longer than a fixed length.
* [DECISION-18: Piped text has the label <stdin>](DECISION-18.md) - A result from piped text uses the rg label <stdin> and the line numbers of the piped text.
* [DECISION-19: The size limit counts characters](DECISION-19.md) - The limit on the text that jag returns is a count of characters.
* [DECISION-20: A default size limit applies with --ask or --json](DECISION-20.md) - With --ask or --json, jag applies a default size limit for an agent; the user can raise it or turn it off. With no question, no default limit applies.
* [DECISION-21: jag leaves out whole results with the lowest rank first](DECISION-21.md) - To stay in the limit, jag removes whole results, starting with the lowest rank.
* [DECISION-22: All text that jag writes to standard output counts toward the size limit](DECISION-22.md) - Labels, the structured wrapper, and notices on standard output count; text on the error stream does not.
* [DECISION-23: jag cuts a top result that is larger than the limit](DECISION-23.md) - When the top result alone is larger than the limit, jag cuts it, marks the cut, and says so.
* [DECISION-24: The notice gives the count and how to raise the limit](DECISION-24.md) - When jag leaves out results, the notice gives their number and how to raise the limit.
* [DECISION-25: A size limit that is not valid is a usage error](DECISION-25.md) - A limit of zero, a negative limit, or a value that is not a number gives exit code 2.
* [DECISION-26: Leaving out results has its own exit code](DECISION-26.md) - When jag leaves out results to stay in the limit, it exits with its own code above 2.
* [DECISION-27: Only an explicit option turns on structured output](DECISION-27.md) - Text is the default, also in a pipe; an option turns on structured output.
* [DECISION-28: Structured output has a field for each item that the text shows](DECISION-28.md) - Each label, count, mark, and notice of the text is a named field; each result has its rank and no score.
* [DECISION-29: In text mode, notices go to the error stream](DECISION-29.md) - Text mode writes results to standard output and notices to the error stream; structured mode writes all of it in the structure.
* [DECISION-30: Structured mode always writes a complete output](DECISION-30.md) - With no results, structured mode writes an empty result list and the summary fields.
* [DECISION-31: The command takes the term and the paths, and the question only from --ask](DECISION-31.md) - The form is jag [OPTIONS] TERM [PATH...], with the term first as in rg. The question comes only from the option --ask "QUESTION".
* [DECISION-32: A term with no question works as plain rg](DECISION-32.md) - With no question, that is with no --ask option, jag makes no model call, has no cost, and works as rg.
* [DECISION-33: The term is a regular expression, and -F makes it fixed text](DECISION-33.md) - The term is a regular expression, as in rg; the -F option makes it fixed text.
* [DECISION-34: Release 1 keeps the rg options that people use most](DECISION-34.md) - jag keeps a fixed set of rg options that people use most, in the rg form; any other option gives the rg text unrecognized flag and exit code 2.
* [DECISION-35: With no path, jag searches the current folder or reads the pipe](DECISION-35.md) - With no path, jag searches the current folder, or reads standard input when text comes in through a pipe.
* [DECISION-36: The user can give any mix of files and folders](DECISION-36.md) - jag accepts several paths, and each path can be a file or a folder, as in rg.
* [DECISION-37: jag shows progress only in a terminal](DECISION-37.md) - While jag ranks, it shows a progress line on the error stream only when that stream is a terminal.
* [DECISION-38: Color works as rg --color=auto](DECISION-38.md) - jag colors the output only in a terminal, with the rg color codes, and --color=never or always changes that.
* [DECISION-39: When the user stops jag, it stops at once with no partial results](DECISION-39.md) - On Ctrl-C or a closed pipe, jag stops, starts no new model call, and shows no partial results.
* [DECISION-40: The cost is the billed amount in US dollars](DECISION-40.md) - jag shows the amount that the service billed, in US dollars; with no billed figure, it shows a labeled estimate.
* [DECISION-41: With --ask in text mode, the cost line goes to the error stream after each search](DECISION-41.md) - With --ask, text mode writes a cost line to the error stream after each search, also in a pipe; structured mode has a cost field; with no question, text mode writes no cost line.
* [DECISION-42: The report counts results scored and results skipped](DECISION-42.md) - jag shows the results it scored and one count for each reason that it did not score a result; together they are all results found.
* [DECISION-43: A search with no model call reports a cost of zero and the reason](DECISION-43.md) - With no question, jag makes no model call; with --json, it reports a cost of zero and says why.
* [DECISION-44: A failed or stopped search reports the cost up to that point](DECISION-44.md) - The error message gives the cost that jag paid before the failure or the stop.
* [DECISION-45: A missing cost figure never fails the search](DECISION-45.md) - When the service gives no cost figure, jag shows the count and marks the cost as not available.
* [DECISION-46: jag scores each search again and does not reuse scores](DECISION-46.md) - Release 1 keeps no scores between searches; a repeated search pays the model service again.
* [DECISION-47: The cost-limit exit code wins over the left-out exit code](DECISION-47.md) - When a search reaches the cost limit and also leaves out results, jag exits with the cost-limit code.
* [DECISION-48: The readiness check exits 0 or with the code of the first cause](DECISION-48.md) - The readiness check exits with code 0 when all five items pass, and otherwise with the code of the first cause that fails.
* [DECISION-49: Plain rg mode needs no key](DECISION-49.md) - A term with no question makes no model call, so jag works with no stored key.
* [DECISION-50: The -A, -B, and -C options set the context lines of a result](DECISION-50.md) - The grep context options set the lines around each match; with no option, jag uses its default.
* [DECISION-51: jag goes public as a new repository with a clean history](DECISION-51.md) - A new public repository gets a clean history. The private repository stays private as ai-ready-future/jag-private, and its history is not rewritten.
* [DECISION-52: The failure limit comes from the timeout and the retry wait](DECISION-52.md) - When the model service does not answer, the time limit is 2 × the timeout + the retry wait, not a fixed number.
* [DECISION-53: An agent skill is not an editor plugin](DECISION-53.md) - The installable jag skill is text for an agent, so it is outside the non-goal 'no GUI, web app, or editor plugin'; SCOPE-08 does not change.
* [DECISION-54: The skill teaches jag as an enhanced rg, with no advice on when to use which tool](DECISION-54.md) - The jag skill tells the agent to use jag in place of rg and shows how jag and --ask work; it gives no advice on when to use which tool.
* [DECISION-55: After jag fails, the skill tells the agent to tell the user, with no fallback rule](DECISION-55.md) - When jag cannot run, the skill tells the agent to give the user the cause and the fix that jag writes; it says nothing about other tools.
* [DECISION-56: The skill tells the agent that --ask exists; the agent decides when to use it](DECISION-56.md) - The skill shows jag TERM PATH (as rg, no cost) and --ask (a paid model call) and says that --ask exists; it does not tell the agent to always ask a question.
* [DECISION-57: A maintainer approves the private-data run of a fork pull request before the merge](DECISION-57.md) - The private-data check of a fork pull request runs only after a maintainer approves each run. A fork pull request merges to main only after an approved run passes.
* [DECISION-58: The user chooses a Clef server with the base URL setting](DECISION-58.md) - The user sets the same base URL setting that an AI gateway uses to the address of a Clef server; jag adds no separate Clef setting.
* [DECISION-59: A Clef server needs no key](DECISION-59.md) - On a base URL that is not TypeSafe, a key is optional; jag sends a key only when the user sets one, and a TypeSafe key never goes to another host.
* [DECISION-60: jag does not check where the model server runs](DECISION-60.md) - jag sends text to the base URL that the user sets and does not decide if the server is local; the user keeps the data inside HIPAA limits, and the README says so.
* [DECISION-61: jag does not care which Clef model the server runs](DECISION-61.md) - The user does not name Clef or Clef-Flash, and jag does not check the model; the server scores with the model that it runs.
* [DECISION-62: jag makes no quality claim for a Clef server](DECISION-62.md) - The quality numbers of jag are for Jev only; the README says so and points the user to the measure on their own questions.
* [DECISION-63: jag has no speed target with a Clef server](DECISION-63.md) - The 5-second search target is for Jev only; with a slow Clef server, the user can raise the timeout.
* [DECISION-64: The cost of a Clef search is not available](DECISION-64.md) - A Clef server sends no bill, so jag shows the count and marks the cost as not available, as DECISION-45 says.
* [DECISION-65: A search still works when one call is too long for the server](DECISION-65.md) - When a call is too long for a Clef server, jag sends smaller calls, so that the search still works and does not fail.
* [DECISION-66: The private-pattern check is on by default for each model service](DECISION-66.md) - jag checks snippets for private patterns before each call to TypeSafe, an AI gateway, or a Clef server; only the user can turn the check off.
* [DECISION-67: jag skips a snippet that matches a private pattern](DECISION-67.md) - jag does not send or score a snippet that matches a private pattern, and the result lists the line as not scored, with the reason.
* [DECISION-68: The private patterns are a built-in list plus a list of the user](DECISION-68.md) - jag has built-in patterns for keys, tokens, and passwords, and the user can add patterns in the config file, for example patient IDs.
* [DECISION-69: The release after release 1 serves users whose text must stay on the machine](DECISION-69.md) - The local model option moves to the release after release 1, before release 2, so users whose text must not leave the machine can use jag with a Clef server.
* [DECISION-70: The maintainer runs the held-out evaluation once, on their own machine, with the Rust jag](DECISION-70.md) - The held-out set stays private. Before the first release tag, the maintainer runs the Rust jag once on the held-out split on their own machine, and only a summary of the numbers goes public.
* [DECISION-71: jag calls a server with no key when the user sets none](DECISION-71.md) - On a base URL that is not TypeSafe, jag calls with no key when the user sets none; a server that refuses the call for a key gives the key-not-accepted failure.
* [DECISION-72: jag sends the model name that the user set, or its default](DECISION-72.md) - jag sends the model name that the user set to a Clef server, or its default model name when the user sets none; the server uses its own model.
* [DECISION-73: An error or an answer that jag cannot read gives the service-down failure](DECISION-73.md) - When the server sends an error or an answer that jag cannot read, jag fails with the service-down code; the message gives the base URL and the status.
* [DECISION-74: The report of the text that leaves the machine names the host](DECISION-74.md) - The report of which text leaves the machine always names the host of the base URL: TypeSafe, an AI gateway, or a Clef server.
* [DECISION-75: The readiness check of a server with no key reports the server items](DECISION-75.md) - For a server with no key, the readiness check reports whether the server is reachable and answers a scoring call; the key items say not needed, and credit says not available.
* [DECISION-76: jag skips a snippet that is too long for the server by itself](DECISION-76.md) - When one snippet alone is too long for the server, jag does not score it and lists it as not scored, with the reason too long for the server.
* [DECISION-77: The private-pattern check examines all text that jag sends](DECISION-77.md) - The check examines the question and each result with its lines around the match; when the question matches, jag stops before any call with a clear message.
* [DECISION-78: A pattern of the user that is not valid stops jag with exit 2](DECISION-78.md) - When a pattern in the list of the user is not valid, jag stops before any model call with exit 2 and names the pattern.
* [DECISION-79: Held-back lines add no exit code](DECISION-79.md) - A search that holds lines back gets the exit code that it gets without them; the report counts the held-back lines, and the cost-limit code still wins.
* [DECISION-80: One setting turns off the built-in list and the list of the user](DECISION-80.md) - When the user turns the private-pattern check off, both lists are off; the report says that the check is off.
* [DECISION-81: The preview of the text that leaves the machine lists the held-back lines](DECISION-81.md) - The preview lists each held-back line with its reason; a term with no question makes no model call, so jag does not check it.
